# 稳定性与解码策略

## 核心边界

- 正文及其字符、字节范围必须一致。原始文本的损坏替换发生在生成范围之前，不放宽规范化 UTF-8 正文的读取校验。
- 最近阅读时间和分片缓存是附属数据：时间戳异步尽力写入；缓存故障时从正文生成并校验内存范围，仍允许阅读。
- 自动保存进度失败时记录诊断，保留内存位置，后续阅读操作重新尝试写入，不产生未处理的异步异常。
- 导入失败且尚未取得书籍 ID 时，先查询书籍与导入日志中的文件引用。查询失败或仍有引用就保留正文；仅明确无引用时删除文件。
- 已明确编码的 BOM 文本发生局部损坏时，以 U+FFFD 替换并报告告警。告警随 worker 清单、导入结果传至书架，支持批量累积和手动关闭。
- 文件大小、正文长度、外键、章节范围等现有保护继续保留。

## GB18030 映射来源

使用 [WHATWG Encoding Standard](https://encoding.spec.whatwg.org/#gb18030-decoder) 的状态机与离线索引，不增加系统字符集或原生构建依赖：

- [双字节索引](https://encoding.spec.whatwg.org/index-gb18030.txt)
- [四字节范围索引](https://encoding.spec.whatwg.org/index-gb18030-ranges.txt)

将两份原始文件放入同一目录后，可在仓库根目录重新生成：

```sh
python3 tool/generate_gb18030_data.py /path/to/index-directory
dart format lib/core/encoding/gb18030_data.dart
```

生成文件头部记录原始索引的 SHA-256，许可证保存在 `third_party/whatwg_encoding_LICENSE`。映射表是标准数据，解码算法不针对特定书籍或单个生僻字打补丁。

## 验证范围

回归覆盖导入读取与撤销双重故障、引用查询不可用、只读数据库阅读和进度重试、缓存降级后的范围检查、Unicode 分片连续性、全部 23940 个双字节索引、四字节区间与错误序列、BOM 文本局部修复，以及中英文告警和小屏幕大量告警展示。

修复不会自动重建此前已被错误解码的书籍；旧 GB18030 书籍若已出现替换字符，需要从原始文件重新导入。
